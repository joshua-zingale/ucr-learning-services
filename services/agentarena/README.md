Agent Arena is a web service for creating, configuring, and sharing agentic
chatbots. The intent for Agent Arena is that it would be easily extensible with
new agent types that use different backends with unique configuration schemata.

# Goal

After a deployment of an AI Tutor in Fall of 2025 at UC Riverside, and after
speaking with faculty across departments, it became clear that every instructor
has a different idea of how an "AI Tutor" should function for students. Thus, we
sought to develop a platform that would facilitate the hosting of chatbot agents
that can be greatly customized.

# Architecture

Agent Arena's architecture reflects the desire for customizability.

At its core, Agent Arena manages _conversations_, which store _messages_, some
of which are from _users_ and others from AI _agents_.

## REST

Agent Arena supports a RESTful API at `/api/...`. Messages thus, for example,
are posted to conversation 5 with a POST request to
`/api/conversations/5/messages`.

## Front End

The front end presents a user-friendly interface to the RESTful API, serving
HTML, CSS, and JavaScript.

## Database

Agent Arena uses Postgres as its database. [db/mocks/0001.sql](./db/mocks/0001.sql) may be run to populate the database with mock data to get it working.

## Agents

One way to provide customizability for AI Agents is to have a robust
configuration, whereby an agent creator could specify exactly the behavior he
wants. However, (1) there are many possible architectures for providing agentic
functionality and (2) an exhaustive configuration schema, to be robust, would be
very large. Therefore, Agent Arena divides agents into _agent classes_.

Each agent class defines a configuration schema (via
[JSON Schema](https://json-schema.org/draft/2020-12/)) and a method for
extracting textual responses from an agent. An agent class lives in the database
as a row in the `agent_classes` table and in memory inside an AgentClassDriver.
An agent class lives in the former to enforce data integrity, that each agent
have a valid class, and in the latter to provide each class a fully customized
logic for text generation.

(Ultimately, the configuration page for an agent should be generated by
inspecting the JSON Schema of the configuration. Thus if an agent is of an agent
class that has a string for a system prompt and an integer for context length,
the config page would have two entry fields for the two configurable items.)

To add support for a new LLM provider, say Anthropic, a new agent class would
need to be added to the `agent_classes` table and an AgentClassDriver that
interacts with the Claude API would need to be written as Go code and added to
the AgentClassDriverRegistry.



# sqlc

This project uses [sqlc](https://sqlc.dev/) to generate type-safe code that
interacts with the database.

The `sqlc` utility is used to generate
[./pkg/database/query.sql.go](./pkg/database/query.sql.go) from
[./pkg/database/query.sql](./pkg/database/query.sql). That is, it generates Go
functions from a file containing SQL queries. This approach has the advantage of
having the freedom to write queries natively in SQL while also getting type-safe
Go code without having to write boilerplate functions by hand.

The config for `sqlc` is [./sqlc.yml](./sqlc.yml).

# Current State

Agent Arena is very early in development, with only a shell of the desired
features present.

Permissions management is rudimentary but provides a solid foundation.

Ollama is the only LLM provided for which support has been added, and only
minimally. The only configuration item is the system prompt.

The RESTful API lacks many needed endpoints, such as the creation and deletions
of agents and conversations and the granting and revocation of permissions

The front end is un-styled and poorly organized with JavaScript shipped in the
same file as the HTML.

Note that something like

```sql
insert into agent_classes(agent_class_id, name) values
('ollama', 'Ollama');
```

must be run on the database before the web server will function because the code currently assumes the existence of `ollama` as an agent class in the database.
